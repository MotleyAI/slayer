# Upgrading to 2.0

This page lists what changes for you when you move from SLayer 1.x to 2.0: first every breaking change, grouped by
where you meet it, then what 2.0 deprecates and 3.0 will remove. Each entry shows what you wrote on 1.x and what to
write on 2.0.

Stored models, queries and memories upgrade themselves on load; nothing below asks you to edit stored documents by
hand unless it says so.

## Part 1: breaking changes

### Formulas, filters and expressions

Every text position of a query (formulas, filters, computed dimensions, `order`) and of a model (column `sql`,
measures, model filters) reads one SQL-like grammar.

**Double quotes name a column.** Strings take single quotes. When a column of the quoted name exists, the comparison
silently runs against that column; otherwise it fails with an error saying strings use single quotes.

<!-- docs-guard: skip -->
```json
{"source_model": "orders", "filters": ["status = \"paid\""]}
```

```json
{"source_model": "orders", "filters": ["status = 'paid'"]}
```

**Backslash is an ordinary character in a string.** Escape a quote by doubling it. On 1.x, `'O''Brien'` silently
became `'OBrien'` and `'C:\temp'` held a tab.

<!-- docs-guard: skip -->
```json
{"source_model": "people", "filters": ["name = 'O\\'Brien'"]}
```

```json
{"source_model": "people", "filters": ["name = 'O''Brien'"]}
```

**`--` starts a comment** that runs to the end of the line. `amount --1` is now `amount`; write `amount - -1`.

**`|` is not an operator.** Concatenate with `||` or `concat()`.

<!-- docs-guard: skip -->
```json
{"source_model": "people", "dimensions": [{"expression": "first | ' ' | last", "name": "full"}]}
```

```json
{"source_model": "people", "dimensions": [{"expression": "first || ' ' || last", "name": "full"}]}
```

**Variables supply values only.** A `{var}` is a value inside quotes, a bare number or boolean, or a whole `IN` list.
Column names, conditions and function names go in the query text itself.

<!-- docs-guard: skip -->
```json
{"source_model": "orders", "filters": ["{col} = 'paid'"], "variables": {"col": "status"}}
```

```json
{"source_model": "orders", "filters": ["status = '{s}'"], "variables": {"s": "paid"}}
```

**Bare `current_date` and `current_timestamp` are the database clock**, even on a model with a column of that name.
Double-quote the column to reach it: `d < "current_date"`.

**One LIKE pattern language on every database.** `%` and `_` are the only wildcards, `\` escapes them, `[` is a
literal character (it was a character class on SQL Server), and LIKE is case-sensitive on SQLite as elsewhere. Use
`ILIKE` for a case-insensitive match.

<!-- docs-guard: skip -->
```json
{"source_model": "stores", "filters": ["name LIKE 'a%'"]}
```

```json
{"source_model": "stores", "filters": ["name ILIKE 'a%'"]}
```

**`greatest` and `least` skip NULL arguments on MySQL, BigQuery and ClickHouse**, as they already did elsewhere. Spell
out the NULL test if you relied on a NULL result:
`CASE WHEN a IS NULL OR b IS NULL THEN NULL ELSE greatest(a, b) END`.

**Text compared with a number compares as numbers.** Text that is not a number reads as NULL. Redshift, Databricks,
Spark and Oracle refuse this comparison. Compare with a string to keep text ordering, or `CAST` explicitly.

<!-- docs-guard: skip -->
```json
{"source_model": "codes", "filters": ["code > 5"]}
```

```json
{"source_model": "codes", "filters": ["CAST(code AS DOUBLE) > 5"]}
```

**`ln`, `log`, `log10`, `log2`, `sqrt` and `pow` return NULL outside their domain** instead of failing (SQLite) or
returning `-inf` / `NaN` (DuckDB); a literal out-of-domain call such as `ln(0)` is refused. Wrap the call in
`coalesce` for a fallback value.

**Every branch of `CASE`, `iif`, `coalesce` and `ifnull` has one type, on every database.** 1.x already refused a
plain mixed-type `CASE`; it now also refuses branches typed by arithmetic, `||`, `concat` or a joined column, a `CASE`
inside an aggregate, and mixed `coalesce` / `ifnull`. `CAST` the odd branch.

<!-- docs-guard: skip -->
```json
{"source_model": "orders", "dimensions": [{"expression": "coalesce(amount, 'n/a')", "name": "shown"}]}
```

```json
{"source_model": "orders", "dimensions": [{"expression": "coalesce(CAST(amount AS TEXT), 'n/a')", "name": "shown"}]}
```

**`first` and `last` without a ranking key, grouped by a computed date or timestamp, rank by that expression.** 1.x
ranked by the first time column the expression read. The expression has one value per group, so pass the ranking key
explicitly.

<!-- docs-guard: skip -->
```json
{"source_model": "orders", "dimensions": [{"expression": "coalesce(shipped_at, created_at)", "name": "effective"}], "measures": ["last(amount)"]}
```

```json
{"source_model": "orders", "dimensions": [{"expression": "coalesce(shipped_at, created_at)", "name": "effective"}], "measures": ["last(amount, shipped_at)"]}
```

**A root-model prefix is resolved, not stripped from the text.** Text inside quotes stays as written (1.x turned
`'see orders.x'` into `'see x'`), a path such as `orders.orders.status` through a join named like the root reaches
that join, and a stage name works as a qualifier in a later stage.

### Lists

**`length(list)` counts distinct non-NULL elements**: `["go", "sql", "go"]` has length 2. Count elements with
repeats with `count(list.*)`.

```json
{"source_model": "contractors", "dimensions": ["id"], "measures": [{"formula": "count(skills.*)", "name": "n"}]}
```

**A list whose `element_type` is `UNKNOWN` no longer has `length`**; only NULL tests and `count` remain. Declare the
column's `element_type` to read its elements.

### Models and datasources

**A datasource custom granularity named like a new library function is renamed on first load** to
`<name>_granularity` (`left` becomes `left_granularity`), with every stored reference rewritten. Queries you send use
the new name. The newly reserved names are `acos`, `ascii`, `asin`, `atan`, `atan2`, `cbrt`, `chr`, `concat_ws`,
`cos`, `date_trunc`, `div`, `ends_with`, `ilike`, `json_extract`, `json_extract_path_text`, `json_extract_scalar`,
`json_value`, `jsonb_extract_path_text`, `left`, `lpad`, `pi`, `regexp_extract`, `regexp_like`, `regexp_replace`,
`repeat`, `reverse`, `right`, `rpad`, `sin`, `split_part`, `starts_with`, `strpos` and `tan`.

**A custom aggregation named like one of these functions keeps working inside its model**, and every save, load and
query response through it carries a `library_name_shadow` warning. Rename the aggregation to silence it.

**Postgres sets the statement timeout once per connection** instead of in a transaction around every query. A
datasource behind a transaction-mode pooler (such as PgBouncer in transaction mode) must opt back in:

```yaml
name: warehouse
type: postgres
host: pgbouncer.internal
transaction_pooler: true
```

### Query JSON

**A serialized time dimension carries its column as a dotted string.** The object form is still accepted as input.

<!-- docs-guard: skip -->
```json
{"source_model": "orders", "time_dimensions": [{"dimension": {"name": "created_at", "model": "customers"}, "granularity": "month"}]}
```

```json
{"source_model": "orders", "time_dimensions": [{"dimension": "customers.created_at", "granularity": "month"}]}
```

### Result values

REST, MCP and the CLI encode result values one way:

| Value | 1.x | 2.0 |
| -- | -- | -- |
| Decimal (JSON) | `"12.30"` | `12.30` |
| NaN, ±Infinity (MCP and CLI JSON) | `NaN`, `Infinity` (invalid JSON) | `null` |
| Timestamp (MCP and CLI JSON) | `"2024-01-02 03:04:05.500000"` | `"2024-01-02T03:04:05.500000"` |
| Bytes | `"b'\\xde\\xad'"` (MCP, CLI); garbled (REST) | `"\\xdead"` |
| Interval (MCP and CLI) | `"1 day, 2:00:00"` | `"P1DT2H"` |
| NULL (MCP csv) | `None` | empty cell |
| Boolean (csv, markdown, table) | `True` / `False` | `true` / `false` |
| NaN, ±Infinity (csv, markdown, table) | `nan` / `inf` | `NaN` / `Infinity` |

**A plain facade `SELECT` returns every record.** Over the PostgreSQL wire facade and Flight SQL, a `SELECT` without
an aggregate, `GROUP BY` or `DISTINCT` returned distinct rows on 1.x; it now returns one row per record. Add
`DISTINCT` for the old result: `SELECT DISTINCT status FROM orders`. List, bytes and interval columns, which 1.x
refused to select, return as text.

### Python API

**Moved modules raise an `ImportError` naming their new path.** Change the import; the names inside are unchanged
unless noted below.

| 1.x | 2.0 |
| -- | -- |
| `slayer.sql.client` | `slayer.database.client` |
| `slayer.sql.engine_factory` | `slayer.database.engine_factory` |
| `slayer.sql.sqlite_introspect` | `slayer.database.sqlite_introspect` |
| `slayer.sql.conformance` | `slayer.database.conformance` |
| `slayer.engine.ingestion` | `slayer.live_schema.ingestion` |
| `slayer.engine.schema_drift` | `slayer.live_schema.schema_drift` |
| `slayer.engine.schema_scope` | `slayer.live_schema.schema_scope` |
| `slayer.engine.introspect_utils` | `slayer.live_schema.introspect_utils` |
| `slayer.engine.broken_dependents` | `slayer.live_schema.broken_dependents` |
| `slayer.engine.internal_tables` | `slayer.live_schema.internal_tables` |
| `slayer.engine.fk_edges` | `slayer.live_schema.fk_edges` |
| `slayer.storage.type_refinement` | `slayer.live_schema.type_refinement` |
| `slayer.engine.home` | `slayer.engine.population.home` |
| `slayer.engine.dimension_routing` | `slayer.engine.population.dimension_routing` |
| `slayer.engine.filter_reachability` | `slayer.engine.population.filter_reachability` |
| `slayer.engine.join_safety` | `slayer.engine.cardinality.join_safety` |
| `slayer.engine.unrelated` | `slayer.engine.cardinality.unrelated` |
| names imported from `slayer.engine.population` | `slayer.engine.population.inference` |
| names imported from `slayer.engine.cardinality` | `slayer.engine.cardinality.inference` |
| `slayer.engine.syntax` | `slayer.core.syntax` |
| `slayer.core.formula` | `slayer.core.syntax` |
| `slayer.osi.expression` | `slayer.importers.aggregates` |

Three of these are not drop-in:

- `parse_filter_expr` is gone: `slayer.core.syntax.parse_expr` reads SQL forms everywhere.
- `parse_formula(named_measures=...)` expanded saved measures; `parse_expr` returns them as plain `Ref`s, and
  `AggCall` / `Arith` / `TransformCall` replace `ArithmeticField`, `TransformField`, `MixedArithmeticField`,
  `AggregatedMeasureRef` and `FieldSpec`. `TIME_TRANSFORMS` and `TIMELESS_TRANSFORMS` live in `slayer.core.enums`.
- `convert_expression` takes `sql_dialect=` in place of `percentile_unsupported=`.

```python
from slayer.core.syntax import parse_expr
from slayer.core.enums import TIME_TRANSFORMS

tree = parse_expr("status = 'x' AND amount <> 3")
```

**Loggers follow the module paths**: configure `slayer.live_schema.ingestion` and `slayer.database.client` instead of
`slayer.engine.ingestion` and `slayer.sql.client` (likewise `schema_drift`, `schema_scope`, `type_refinement`,
`engine_factory` and `sqlite_introspect`).

**Ingestion and drift validation take the SQL client.** `ingest_datasource()`, `ingest_datasource_report()`,
`ingest_datasource_idempotent()` and `validate_datasource()` require `client=`; `validate_datasource()` no longer
takes `sql_clients=`.

```python
models = await engine.ingest(ds)  # or ingest_datasource(ds, client=engine.client_for(ds))
dropped = await validate_datasource(datasource=ds, models=models, client=engine.client_for(ds))
```

**Converters read the database only through `collect_metadata`.** `DbtToSlayerConverter` and `OsiToSlayerConverter`
no longer take `sa_engine`, and every parameter after `data_source` is keyword-only. Without `collect_metadata`,
`convert()` runs offline and reports what it skipped.

```python
converter = DbtToSlayerConverter(project, "warehouse", target_dialect="postgres")
await converter.collect_metadata(client=engine.client_for(ds))
result = converter.convert()
```

**Custom storage backends implement the current hooks.** 0.9.x-style subclasses are no longer adapted (the
`slayer.storage.legacy_backends` module is gone): implement `_save_datasource_impl` instead of overriding
`save_datasource`, and return `(memories, failed_rows)` from `_list_memories_rows`.

**Column types come from `get_result_column_types`.** `get_column_types_sync()`, `SlayerSQLClient.get_column_types()`,
`DelegatingSqlClient.get_column_types()` and `SlayerQueryEngine.get_column_types()` are gone, with
`type_categories`, `adapt_client` and `LegacyTypeCategories`. The replacements return `ResultColumnType` objects, not
category strings; a custom client implements `get_result_column_types(sql)`.

**EXPLAIN goes through the client's `explain`.** `SqlDialect.build_explain_sql()` is gone (use
`explain_statements()`), and a custom client implements `explain(statements: ExplainStatements)`. A
`DelegatingSqlClient` subclass that overrides only `execute` has its EXPLAIN served by the wrapped client, bypassing
its own `execute`; override `explain` too to route it.

```python
class Gateway(DelegatingSqlClient):
    async def execute(self, sql):
        return await my_gateway.run(sql)

    async def explain(self, statements: ExplainStatements):
        return await my_gateway.run_explain(statements)
```

**The SQL client refuses session and transaction statements.** `execute("SET ...")`, `BEGIN`, `COMMIT`, `USE` and
the like raise `SessionStatementRefused`; SLayer manages sessions and transactions. Set statement timeouts and session
settings on the datasource.

**`TimeDimension.dimension` is a `str`**, the dotted column path (`"orders.created_at"`), not a `ColumnRef`.

```python
model, _, column = time_dimension.dimension.rpartition(".")
```

**Smaller removals:**

- `MemoryNotFoundError.identifier`: read `memory_id`.
- `SlayerQuery.strip_source_model_prefix()`, `slayer.core.query.has_variable_syntax`, `query_variable_surfaces`,
  `slayer.core.time_spine.mentions_spine` and `ComputedDimension.substituted()`: root qualifiers and variables resolve
  when the query binds, so drop the calls.
- `substitute_variables(..., escape=...)`: the parameter is gone; pass `backslash_escapes=` only.
- `ModelMeasure.substituted(formula)` requires `variables=`.
- `slayer.core.format.list_json_text`: use `encode_json(value)`.
- `apply_session_policy` and `policy_column_checks` take a parsed statement and an `SqlDialect` instead of SQL text
  and a dialect name.
- The dialect methods `statement_timeout_sql()` and `correlated_setting_sql()`, and
  `slayer.sql.client.build_sql_model_trial_query`.
- `SCALAR_FUNCTIONS` is no longer re-exported from `slayer.core.query` or `slayer.core.models`; import it from
  `slayer.core.keys`.
- `run_over_caller_engine`, `warn_deprecated(location=)` with `WarningLocation`, and `DriverFacts.bundled_non_default`.

### MCP, CLI and environment

**The MCP `inspect_model` tool is gone.** Call `inspect` with `entity_type="model"` and `compact=False`; without
`compact=False` you get the short view.

```text
inspect(reference="warehouse.orders", entity_type="model", compact=False)
```

**`--models-dir` is gone from every command**; pass the path to `--storage`: `slayer mcp --storage ./slayer_data`.

**`SLAYER_MODELS_DIR` is silently ignored.** Nothing warns: SLayer starts an empty store in the platform default
directory. Rename the variable to `SLAYER_STORAGE`.

**Cube and dbt imports read the datasource.** `slayer import-cube` and `slayer import-dbt` connect to `--datasource`
when it can be reached and take column types from it (`import-osi` already did); an unreachable datasource still
imports, with a note that types were not checked. On Postgres, Redshift, Snowflake and Oracle datasources, unquoted
mixed-case names are stored in lowercase (`Sales.OrderItems` becomes `sales.orderitems`, column `OrderAmount`
becomes `orderamount`), and a project with such names is refused when `--datasource` is not configured at all.
Constructs the target database cannot run (a MySQL `median`, a `max` over a column of unknown type, an OSI
`PERCENTILE_DISC`) are dropped and listed in the conversion report. Re-import against a configured datasource and
update queries that use the old mixed-case names.

**Ossie export and import moved to `0.3.0.dev0`.** `slayer export-osi` writes `version: 0.3.0.dev0` (1.x wrote
`0.2.0.dev0`), so a consumer that validates exports against the 0.2 schema must move to 0.3. `slayer import-osi`
drops, with a report entry, three kinds of field that 1.x imported: one reading a label its query source outputs more
than once (`SELECT o.id, c.id, …`), one transforming the source column of its own name (`status: UPPER(status)`), and
one reading a source column whose name another field holds. Alias the duplicated labels in the source query and give
such fields their own names.

### Installation

- `motley-slayer[postgres]` installs only psycopg, and `[mysql]` only pymysql; `[all]` drops psycopg2-binary, asyncpg
  and aiomysql. A connection string naming `+psycopg2`, `+asyncpg` or `+aiomysql` needs that driver installed
  directly: `pip install 'motley-slayer[postgres]' asyncpg`.
- SQLAlchemy 2.0.43 or newer and pyparsing 3.1 or newer are required.

## Part 2: deprecated in 2.0, removed in 3.0

Each deprecated form still works in 2.x. Using it emits a `FutureWarning` in Python and adds a `deprecated_input`
warning (`old`, `new`, `removal`) to the response of every query that runs it and of every REST or MCP save that
stores it; a Python `engine.save_model(model, warnings_out=notes)` call appends it to `notes`. What is stored is
always the replacement.

**`strict`.** A query carrying `strict` is converted: `strict: true` becomes `to_many_handling: "error"`, and
`strict: false` is dropped. An explicit `to_many_handling` wins. 1.x refused `strict` on new queries; stored queries
that carry it upgrade silently.

<!-- docs-guard: skip -->
```json
{"source_model": "orders", "dimensions": ["status"], "measures": ["sum(customers.spend)"], "strict": true}
```

```json
{"source_model": "orders", "dimensions": ["status"], "measures": ["sum(customers.spend)"], "to_many_handling": "error"}
```
