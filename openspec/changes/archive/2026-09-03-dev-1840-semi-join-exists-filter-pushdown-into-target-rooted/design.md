# Design — DEV-1840 semi-join filter pushdown

## Context

See proposal.md — Why. Today `_conjunct_disposition` (`stage_planner.py:1805`) is two-way: every ref attributable from the producer root → re-rooted inline `BoundFilter`; else → `UnreachableFilterDroppedWarning`, collected onto `RegroupAttachPlan.dropped_filter_warnings` and surfaced via `_collect_dropped_filter_warnings` / `_raise_on_strict_events` (`query_engine.py:314-385`). The only correlated-EXISTS emission is the RLS one (`session_policy._build_exists`, `session_policy.py:168`), including ClickHouse ≥ 25.4 gating + `allow_experimental_correlated_subqueries=1` attachment — but that attachment happens only inside `apply_session_policy`. `join_sync` mirrors INNER joins only; the default join type is LEFT, so most real graphs have no stored reverse edges. Codex plan review produced 12 findings (F1–F12); F1–F11 folded below, F12 rejected as redundant with the existing golden corpus (one composite-key N:1 golden added if missing). Interview decisions: same-row grouping, silent pushdown, EXISTS-uniform with ClickHouse guard, consent to update the three DEV-1836 drop-pin tests.

## Goals / Non-Goals

**Goals:** three-way conjunct disposition (inline / semi-join / dropped); one uniform filter semantics with inline as a pure optimization on provably-to-one paths; pushdown reaching every target-rooted producer kind; N:1 byte-identity; the dropped-filter warning and strict error surviving only for genuinely excluded conjuncts.

**Non-Goals:** general bidirectional join traversal (DEV-1853 — this change ships only a scoped inversion helper for EXISTS correlation); recursive boolean lowering of OR-shaped predicates (out-of-scope conjuncts stay dropped+warned, liftable later); unsafe aggregate *inputs* (stay hard errors); dimension attribution/broadcast and AGGREGATE-phase routing (untouched); DEV-1841 attribution.

## Decisions

- **D1 — Three-way disposition, classified over expanded dependencies (F1).** Per ROW conjunct: all refs attributable → inline (unchanged); all refs *path-resolvable* from the root but ≥1 hop not provably to-one → semi-join; else dropped+warned. Classification (safe and pushable alike) resolves each `ColumnSqlKey`'s full Mode-A dependency set (the join paths its SQL actually reads), not just declared key paths — closing the latent inline hole too. *Rejected:* classifying from `walk_value_keys` alone — a derived column crossing a 1:N hop would misclassify as safe.
- **D2 — Pushability scope (F3, F4).** Pushable only when the conjunct's cross-path refs lie on ONE join tree and no OR/NOT node mixes root-local with cross-path refs or spans branches. Root-local refs mixing under pure conjunctive structure (atomic comparisons, AND) push as correlated outer references. Everything else stays dropped+warned. *Rejected:* recursive boolean lowering (per-branch EXISTS under the original OR structure) — significant complexity for a rare shape, and drop+warn is never silently wrong.
- **D3 — Grouping by first reverse hop, connected join tree (F2).** Pushed conjuncts sharing their root-adjacent reverse hop share one EXISTS whose subquery joins the union tree of their paths; all group conjuncts AND-ed — same-related-row semantics exactly where the result spine has it. Distinct first hops → independent EXISTS. *Rejected:* exact-path-set grouping (a `status` conjunct and an `items.sku` conjunct would decouple, admitting customers no single joined tuple qualifies) and one global EXISTS (cross-branch inner joins wrongly require every branch non-empty).
- **D4 — Scoped edge inversion for correlation only (F5).** A reverse hop resolves from a stored edge, else by inverting a stored forward edge (swap `join_pairs`, flip the cardinality label). The via-host path inverts the exact source path the producer re-rooted along (instance-exact). Several candidate forward edges with no stored reverse edge → dropped+warned as ambiguous. Inversion lives in one named helper (join_safety territory) that DEV-1853 later promotes into the shared walker; it never feeds inline/safe classification. *Rejected:* stored-edges-only (the ticket's canonical shape no-ops on default-LEFT graphs); general bidirectional traversal here (cross-cutting refactor on this feature's critical path).
- **D5 — IR carries validated hop descriptors (F8, F9).** New `SemiJoinFilter` on `planned.py`: ordered hop descriptors (target model, oriented `join_pairs`, stable path-node identity for aliasing — repeated models bind aliases per node, not per name; a literal self-join declaration is rejected at model validation, shipped with this change's test stage, since name-keyed paths can never address it), the group's conjuncts as ValueKeys in producer-root coordinates, filter texts for diagnostics. Threaded `_cross_model_inherited_filters` → `_regroup_producer_prebound` → producer `PlannedQuery`, parallel to `bound_filters`; nested producers get it via the same synthesis path. The generator only renders the stored structure — no re-resolution. *Rejected:* path-name tuples resolved again at render time (planner/generator drift, repeated-model ambiguity).
- **D6 — Emission mirrors the RLS EXISTS builder.** `exp.Exists` appended to the producer body's base WHERE: first hop's table as subquery FROM (allocator-assigned alias prefix), correlation equalities from the first hop's oriented pairs (composite keys AND-ed per pair), later hops as inner joins, group conjuncts AND-ed as the terminal predicate; root-local refs render as correlated outer references. `assert_scope_closed` + no-placeholder-leak on the new emission.
- **D7 — ClickHouse plan-driven gating and settings (F6, F7).** One recursive `plan_has_semi_join_filters` predicate over nested plans, used (a) to trigger the version preflight (generalized from RLS-only), (b) by a finalization step that attaches `allow_experimental_correlated_subqueries=1` to planner-emitted SQL (sharing the session-policy settings attachment, coexisting with policy settings, UNION placement covered), on every execution entry point — execute, dry-run, type probe, explain, cache refresh. The guard raises a general clear error (not `ForcedFilterError`) naming the filter and the ≥ 25.4 requirement.
- **D8 — Metadata and strict.** Pushed conjuncts vanish from `dropped_filter_warnings` (silent, uniform with inline); the warning payload, Python warning, and strict error survive only for genuinely excluded conjuncts (unreachable, ambiguous, out-of-scope). Broadcast machinery untouched.
- **D9 — Test-surface protocol.** Executed-value oracles (SQLite + DuckDB) with adversarial data: same-row grouping counterexample; EXISTS ≡ inline on m:1 (same data, declared vs undeclared); zero-related-rows; multi-hop + composite keys with deliberately conflicting rows (F11); ranked/windowed/nested producers executed (F10); repeated-model alias identity (F9). Goldens: new `dev1840_sql_baseline.json`, Tier-1 multi-dialect EXISTS shapes; existing corpus is the N:1 byte-identity tripwire (+ one composite-key N:1 shape if missing). Three DEV-1836 pins updated per consent; a strict-unreachable test replaces the strict-drop pin.

## Risks / Trade-offs

- [Scope-restricted pushdown surprises users with OR filters] → unchanged drop+warn is loud, strict still errors, and the warning text stays actionable; lifting is additive later.
- [Inverted-edge correlation guesses wrong among multiple FKs] → ambiguity fails closed (drop+warn) by D4; adversarial fixtures pin it.
- [Old-ClickHouse regression: queries that executed now fail] → deliberate, enumerated as an approved error-surface flip; error names the version requirement.
- [Settings finalization interferes with RLS-attached settings] → shared attachment helper + a test with both RLS join rules and semi-join filters active.
- [Byte-identity drift on safe shapes] → inline fast path untouched by construction; existing golden corpus as tripwire.

## Migration Plan

One PR on this branch, tests-first; ordered commits: (0) IR + classifier (three-way, expanded deps, inversion helper — no emission yet) → (1) EXISTS emission + grouping → (2) metadata/strict flip + ClickHouse gating/settings → (3) docs + DEV-1836 test updates. Rollback = revert the PR (no storage migrations).
