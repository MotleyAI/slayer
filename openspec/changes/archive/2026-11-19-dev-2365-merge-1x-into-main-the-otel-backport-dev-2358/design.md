## Context

See proposal.md for motivation. `main` already has #602 in its own vocabulary (Ossie names: `population` / `metrics`
/ datasets / fields / relationships) and layout (`slayer/database/client.py`, `slayer/live_schema/*`; the old 1.x
paths are `raise_moved` stubs). #605 is `1.x`'s port of #602 in 1.x vocabulary plus the review fixes of commit
`42c82f0d9`. A trial merge of #605's head into `main` (`cf18f43a9`) conflicts in 52 paths; every `slayer/otel/*`
and `tests/test_otel_*` file conflicts as add/add.

The conflict rules are the DEV-2358 comment "Forward-merge notes (1.x → main)" (items 1–18, "take `main`'s"
unless an item says otherwise), with precedent #600. CI's forward-merge spec check (`scripts/forward_merge_specs.py`,
`openspec/specs/compatibility/forward-merge-specs`) requires every requirement the merged 1.x range adds or modifies
to survive verbatim or be listed in `openspec/forward-merge-ledger.yaml`.

Principles that apply: `python.otel` §3 1 (off unless asked), 2 (fail-silent: the restart and redaction fixes),
3 (no content without the opt-in: the EXPLAIN content tests), 5 (observing changes nothing: the warning-location
tests), 6 (one way in); `system.arc42.md` §3 2 (model truth) and 5 (async-first). No architecture harness changes:
every `architecture/*` path resolves to `main`'s.

Structural cause: none beyond what #605 fixed; each fix is a local defect in shared code, carried by the merge, and
the forward-merge spec check already guards the two lines' specs against silent loss.

## Goals / Non-Goals

**Goals:**
- `main` contains every `1.x` commit, with `main`'s layout, vocabulary and behaviour wherever the notes say so.
- Each shared-code fix has a test on `main` that fails without it.

**Non-Goals:**
- Any change to `architecture/*`.
- 1.x-only behaviour reaching `main`: the bundled-driver warning, the asyncio entry in `_INTERNAL_DIRS`, 1.x's
  `run_sync` change, 1.x-vocabulary docs and examples.
- Changing `main`'s comparison-matrix cells beyond what DEV-2314 adds (C23, C4).

## Decisions

1. **The fixes land through the `1.x` → `main` forward merge, not a separate port**; DEV-2365 is renamed and its branch
   renamed to match. Options: separate port first, then a forward merge / one merge carrying both. Taken: one merge,
   since the merge resolves the same hunks anyway and late #605 fixes come along unchased. (user)
2. **Merge source: #605's head now; `origin/1.x` again once #605 is merged and archived.** The PR opens only after the
   second merge, so `main` receives the archived DEV-2358 change and the final `1.x` specs. (user)
3. **Conflict rules = the DEV-2358 forward-merge notes, precedent #600**, with decisions 4, 5, 6 and 9 as overrides.
   (user)
4. **`main`'s span-tree requirement gains the EXPLAIN clause and scenario** (the 1.x approved wording, adapted to
   `slayer.db.explain`), and the four 1.x EXPLAIN tests are adapted to `slayer.db.explain` instead of dropped
   (overrides notes item 10). Options: A fix here / B leave `main`'s spec stating that every query has
   `slayer.query.run`. Taken: A, per the ruling that findings in code shared with `main` are fixed on both lines.
   (user)
5. **`connection_url()` and `_running_loop_async_engine()` are ported by hand into `slayer/database/client.py`**
   (overrides notes item 4, written when DEV-2365 was a separate port); `main`'s pre-fix `connection_url()` is
   identical to 1.x's. The 1.x paths stay `main`'s stubs. (default)
6. **`slayer/otel/{recorder,exporters,control,middleware}.py` take the `1.x` side verbatim**: their only differences
   from `main` are the fixes. (default)
7. **The 1.x OTel requirements the notes resolve to `main`'s wording get ledger entries**, since the CI check
   requires each one to survive verbatim or be ledgered. (default)
8. **`main`'s Postgres fixtures need no `aclose()` change**: `pg_query_engine` and `owned_query_engine` already release
   the async engine on exit. (default)
9. **DEV-2314:** Q22 / Q27 cells take `main`'s; C23, C4, the `osi_roundtrip` runner mode, its probes, the expectation
   checks and their tests come over in `main`'s vocabulary; `matrix.json` is regenerated by `export_matrix.py`, never
   hand-merged; `test_osi_roundtrip.py` keeps `main`'s timeout and DEV-2236 pointer. (default)
10. **`pyproject.toml` takes `main`'s** (its `all` extra drops 1.x's bundled drivers). (default)
11. **Tests are written on `main` before the merge**, so each fix test fails without its fix; at the merge each test
    file's conflict resolves to those versions. (default)
12. **`customers.yaml`'s `tags` field keeps 1.x's `db_type: 'VARCHAR[]'`** in `main`'s field vocabulary: ingestion and
    Ossie import write it, and the C23 round trip compares models (DEV-2314 design, risk on `customers.yaml`). (codex)
13. **`poetry lock` runs on the merge result unconditionally, then `poetry check --lock`** (notes item 18). (codex)
14. **The done gate runs every `tests/test_otel_*.py` and `tests/pg_facade/test_connection.py`**, serial and under
    `-n`, since the lifecycle fixes touch process-global state. (codex)
15. **`main`'s `db.explain` probe records `db.response.returned_rows`**, as `otel/collection` already requires of
    every database span; the adapted EXPLAIN test asserts it. Options: A add it / B drop the assertion. Taken: A.
    (user)
16. **`main`'s comparison probes are respelled to DEV-1607's query shapes in this change**, since `main`'s runner
    refuses their `{expression, name}` metric entries and C23's "(verified)" cells need a working runner. Options: A
    respell here / B only the C23 probes and the query-backed datasets / C defer 3.5 to a new issue. Taken: A. (user)

## Risks / Trade-offs

- [Git's rename detection carries 1.x hook code into `main`'s moved files] → After resolving, diff each
  `slayer/database/client.py` / `slayer/live_schema/*` / `slayer/engine/field_dependency.py` against `origin/main`;
  the only allowed difference is decision 5 and decision 15.
- [Clean auto-merges carry 1.x vocabulary or behaviour silently] → Diff every auto-merged path against `origin/main`
  (`git diff origin/main --stat` after resolving) and justify each remaining difference against the proposal.
- [#605 changes again before it merges] → The second `origin/1.x` merge brings it; re-run the gate after it.
- [The forward-merge check names requirements only after the second merge] → Ledger them then, before the PR opens.
