## Goals / Non-Goals

**Goals:** one attach mechanism, one classifier-free planner path, one safety authority applied per input role, one render pipeline with one Kahn driver, shared producer nodes, empty guard list. **Non-Goals:** engine-level algebraic IR (nodes stay renderer-internal); aggregate-over-attached (DEV-1847); transform-family-internal gaps (DEV-1846); EXISTS pushdown (DEV-1840); deterministic `first`/`last` tie-breaking (ties stay set-nondeterministic, compared set-wise — F4).

## Decisions

- **D1 — Renderer-internal typed nodes, no engine IR.** A `Node` (name, select AST, schema map slot_id→alias, depends_on) built by one pipeline: base → aggregate → combined → steps → post. The planner contract stays `PlannedQuery`. *Rejected:* a planner-level operator DAG — the issue's non-goal, and node discipline captures the closure-by-construction benefit renderer-side.
- **D2 — Fusion preconditions, not just single-consumer (F5).** Adjacent nodes fuse in emission only when ALL hold: exactly one consumer; no phase boundary crossed; projection order and aliases identical after fusion; no hidden-column trim boundary; no POST consumer of the intermediate schema; no dialect-required CTE boundary. Fusion is an emission decision, never semantic; today's plain-query single SELECT and single-CTE producer bodies are the fusion fixed points. Snapshot tests: plain aggregate + hidden ORDER BY, POST filter, multi-alias measures, dimension-only dedup, empty-base scalar.
- **D3 — Producer identity = complete normalized spec (F1).** Interning key: recursively structural fingerprint of the producer body (`PlannedQuery` content), root model, effective grain, kernel parameters, inherited row-filter conjuncts and their rewrites, and nested producer identities — not the render-level `(keys, join keys)` pair. Negative pins: same aggregate + different inherited filters / frame rewrites do NOT intern. Registry threaded through `plan_query` recursion (plan level) plus a generation-wide rendered-producer map threaded through `_render_producer_split` exactly like the allocator (F6) — the flat hoist already gives every producer CTE top-level ownership, so no LCA machinery is needed. Termination unchanged: grains strictly decrease and identity includes grain. Test contract (step-5 Codex T7): the identity is exposed as `stage_planner.regroup_producer_identity(attach) -> Hashable`.
- **D4 — Explicit producer kernel (F2).** `RegroupAttachPlan` gains a typed kernel: `plain` (grouped aggregate) | `ranked` (ordering key, direction, null policy — the `ranked.py` emission) | `trailing-window` (frame duration, active-time resolution, frame-bound filter rewrites — today's `_wm_` interval join). Each field currently living on `WindowedAggregatePlan`/`RankedAggregatePlan` gets a named home on the kernel before those classes are deleted; the kernel renders as the producer's node chain. *Rejected:* encoding kernels as opaque nested plans only — loses the frame/ordering semantics the renderer must see.
- **D5 — Per-role crossing-input safety (F3).** One predicate (stage-3 D1) applied by input role: filter references and arguments crossing an unproven hop → hard error (both modes); a host-grain wrap's crossing source path → legal (defined over the join result). The class-(d) ledger is organized per role with today's values recorded; newly-rejected shapes are compatibility changes approved by the author, not presumed bugs.
- **D6 — Warnings stay event-based (F7).** Warning payloads live on consumer edges / semantic events (kind + originating filter/dimension/reason), never keyed by producer identity; interning must neither drop nor double-surface them. Pins: shared producer × two consumers warns once per event; two distinct producers with the same user-filter drop warn once; nested duplicates collapse.
- **D7 — One canonical Kahn driver.** The two chains merge into one driver with one batch-dispatch order, chosen at implementation by measuring golden churn; the loser's goldens re-bless as class (b). The `:5739` deadlock backstop survives inside the driver. Subsumes DEV-1799 (closed on landing).
- **D8 — Prove dead before deleting (F9).** Before the legacy arms go: a planner invariant (raise, not assert) that no `CrossModelAggregatePlan` with `cte_root_model=None` survives planning, pinned by a test; then the target-rooted arms and `_guard_target_grain_time_shift` are deleted with it. Mirrors the stage-3 D7 pattern: backstops are replaced, never dropped. Test contract (step-5 Codex T7): the invariant is exposed as `stage_planner.assert_no_unrooted_cross_model_plans(planned)`; its synthetic-bad-plan pin is a transition pin retiring in the same commit that deletes the CMA class, while the plan-walk sweep pin is getattr-guarded and outlives the deletion.
- **D9 — Ranked ties compared set-wise (F4).** Executed-value equivalence for `first`/`last` with tied ranking keys accepts any allowed candidate (the established `test_dev1748_first_last_matrix` convention). No deterministic tie-break is introduced.
- **D10 — Test-surface protocol.** DEV-1836 D10 classes carried forward with class (c) EMPTY: any executed-value change discovered is a bug or an unapproved flip — stop and ask. Suite dispositions per tasks.md task 0.2 (behavior pins ported failing-first before any deletion; mechanism pins retire with their module).

## Risks / Trade-offs

- [Interning merges producers that must differ] → identity includes the complete spec (D3); negative pins land in the same commit as the registry.
- [Kernel model misses a semantic the old plan classes carried] → task 2.0 inventories every field of the three classes and names its destination (kernel field, producer body, or deletion-with-pin) before migration starts.
- [Fusion breaks byte-identity on an unanticipated shape] → fusion preconditions are conservative (fuse only when provably identical); a shape failing them emits an extra CTE (class (b)) rather than wrong SQL; fast-path goldens are the tripwire.
- [Per-role safety flips a shape the author considers legitimate] → class-(d) ledger enumerates each with today's values for explicit approval before implementation.
- [Stacked corpus: DEV-1836 archives first; its computed-dimensions REMOVED targets a drifted name] → flagged to the author for the 1836 branch; this change re-baselines against the post-1836 corpus at implementation start (validate --strict re-run, MODIFIED blocks re-checked).
- [Golden churn obscures a real regression] → executed values pinned unchanged per batch; every class-(b) re-bless runs the executed-value companion suite on SQLite + DuckDB.

## Migration Plan

Ordered revertible stages, each green before the next (see tasks.md): (1) interning; (2) family unification — windowed, ranked-host, host-rooted/filtered-local/grain-host — then delete plan classes + classifier + planner modules + legacy arms; (3) node fold — one pipeline, one Kahn driver, collapsed arms die; (4) CTE-body guard lifts; (5) sweep — meta-test (no coexistence `NotImplementedError` in `slayer/sql/`), docs, perf A/B + RESULTS.md, ledger finalization, close DEV-1799. Rollback = revert the PR (no storage migrations).
